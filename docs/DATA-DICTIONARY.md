# 扫描时效定义

scan_id是扫描事件唯一键，parcel是包裹号。节点按收件、起运、清关、妥投、退运顺序推进；可缺中间节点，但必须有收件。按event_time排序，received_time仅用于上传延迟与重复扫描择优。倒退扫描隔离，不改写先前妥投事件。妥投使用本运输实例内最早有效发生时刻。

## 面单多次启用裁决

同一面单退运后重新启用时，**按每次启用拆成独立运输实例**（`instance_id` = `面单#启用序号`），而不是把多次使用合成一条连续履约链。

- 实例边界：一个实例取得正式妥投或退运扫描后，再次出现收件扫描即开启下一实例。上一实例的妥投与退运只作为历史证据挂在链上（`prior_delivery_at`、`prior_delivery_sources`、`prior_instance_id`），不并入新实例，也不结束新实例。
- 连续追踪：同一实例内按事件时刻连续推进；`chain` 字段给出面单的全部实例顺序。
- 唯一正式妥投：每个面单只有最新实例是当前实例（`current=true`），只有它在时效与对账中产生正式妥投与正式赔付；较早实例标记为“历史”，保留参考值但不再计赔。
- 旧签收不并入：本实例的计时只使用本实例的收件、妥投时钟。旧签收既不能提前结束新一票，也不能抵消新一票的赔付。
- 补传/重试幂等：同一面单、同一节点、同一发生时刻的重复扫描按最早上传（再按scan_id）择优，其余进入隔离（`DUPLICATE_SCAN_EVENT`）并保留为历史证据；重复提交相同输入复用同一批次号，不会重复创建运输实例或重复计赔。
- 同一实例内重复收件（`DUPLICATE_ACCEPT`）、重复妥投（`DUPLICATE_DELIVERY`）、同一实例重复结算（`DUPLICATE_SETTLEMENT`）均被拒绝或隔离，归档还要求每个面单恰有一个正式结算实例（`OFFICIAL_SETTLEMENT`）。

目的地JP/US/DE对应东京/纽约/柏林。时效以目的地工作日小时计算，周末与节假日停表。JP含2026-11-03与11-23，US含11-26，DE含10-03；支持按参数覆盖假日。未妥投计算至as_of，默认2026-11-18T00:00Z。每超时小时赔付1元，上限保价10%，reported为原申报赔付。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的物理结束行号表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。

## 证据归档版本

每个批次只保留一个已发布证据版本。归档内容按正文摘要判重：同源重试、重复点击只复用现有版本，不新增版本。发布在一个事务内完成“旧发布版置为superseded + 写入新发布版”，渲染或写入失败时整体回滚，旧发布版保持可读；`GET /api/runs/<id>/archives/<version>` 可取回任意历史版本。导出证据保留历史签收行（`prior_delivery`）与隔离行（`quarantine`），历史证据不因归档而删除。
